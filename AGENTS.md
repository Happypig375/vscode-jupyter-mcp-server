# Agent contract

## Ownership

- `src/server.ts`, `src/schema.ts`, `src/localOperations.ts`, `src/extension.ts`, and `src/broker.ts` define the MCP boundary and routing.
- `src/notebookOps.ts` owns VS Code notebook operations.
- `src/test/mcp.test.js` covers the public boundary, `src/test/broker.test.ts` covers multi-window routing, and `src/test/mcp.jupyter.test.js` covers Jupyter-backed integration behavior.

## Authoritative 0.4.0 contract

Existing-notebook tools use `notebookRef` for one target and `notebookRefs` for multiple targets. A ref is a direct URI or a short opaque `nb_` handle from `list_notebooks`; handles resolve only against currently open notebooks. `list_notebooks` returns grouped connected windows, including empty groups. `open_notebooks` accepts actual file URIs in `uris` and an optional `windowId`. `create_notebook` accepts `title`.

Tool schemas are strict. Unknown or obsolete keys fail validation. `list_kernels` is read-only; provider setup is explicit through `configure_kernel`; `select_kernel` accepts only an exact listed id. `run_cells` has no kernel hint. User supplied runtime selection takes precedence over defaults.

## Colab setup in 0.5.0

Environment preparation converts a single folder to an untitled Workspace **before** any notebook/runtime exists, using only public `updateWorkspaceFolders(0, 1, { uri: sameRoot, name: ownedDistinctName })`. Persist the request before dispatch, serialize continuations, never replay an unacknowledged conversion, and verify the exact original root/name plus one-root untitled configuration after activation before pinning its URI. Later folder additions may preserve readiness only in that exact pinned Workspace. Restored documents/notebooks/terminals/debugging block conversion; no automatic close/save, private workspace/trust writes or authentication access. Read-only receipt polling must not dispatch the conversion. Existing configured Workspaces are reused. The public API and an isolated live fixture verify the planned first-host refresh and absence of a second refresh on folder append; full Colab readiness still requires actual nonce verification.

Native input actions may use only the fixed `Page.bringToFront` call on the exact marker-bound CDP page, followed by fresh binding/focus verification. Binding and listing must not focus or write. Preserve synchronous `document.hasFocus()` and exact active-input checks for every input write and Enter dispatch. Wait for filtered picker loading to settle before submission; a loading row is not ready. The source picker can open directly at **Select Another Kernel** after a refresh; accept that exact entry point without assuming a preceding suggestions action. A provider handoff can reopen the source picker once: require a new empty prompt and permit only one additional exact Colab selection. Never interpret the old filtered source prompt as a new handoff or loop repeated selections.

Initial controller suggestions can use the exact notebook's relative label in **Select/Change kernel for '…'**, followed by **Select Another Kernel**. Match the platform separators and, in multi-folder windows, the exact owning folder name plus the workbench bullet separator. Bind those labels to the target notebook and preserve exact synchronous header/row checks; do not select a local suggestion or broadly match another notebook's label. First-server mounting can refresh the extension host: retain the server alias, re-list window/notebook handles and reconfigure that exact server with explicit kernel selection and fresh verification. An interrupted in-memory setup receipt is not readiness.

For a local Windows notebook outside every workspace folder, `asRelativePath` returns the filesystem path while the workbench uppercases its drive letter. Apply only that drive-letter display normalization before constructing exact picker headers. Preserve the complete remaining path and do not add a workspace prefix or case-insensitive/basename match.

`list_colab_terminals` and `close_colab_terminals` inspect and explicitly close selected authorized terminals before environment preparation. References bind the latest short-lived per-window inventory and exact live objects. Metadata is not proof of idleness or ownership. Never auto-close restored terminals, expose arguments/environment/history, execute arbitrary shell text, or imply that disposal guarantees graceful command completion. Validate all targets before closure and retain partial/uncertain outcomes.

`prepare_colab_environment` / `get_colab_environment_preparation` are window-scoped and initialized from extension context. `colabEnvironment.ts` owns durable receipts, exact trusted workspace/native binding (plus nonce marker for generated folders), and bounded normal-quit bootstrap for the default installed Windows VS Code 1.142.0 profile. Optional `folderUri` must resolve to an existing local directory; never write a marker or alter trust in a user-selected folder. Generated folders may need user trust before extensions activate. Keep the relaunched GUI visible while background helpers remain hidden. Never force quit, save/discard user work, change argv.json, trust a port alone, or label environment readiness as runtime readiness. Reuse existing open/create notebook tools. Startup with other windows, documents, notebooks, terminals, profiles or unrecognized arguments fails closed; retain normal sign-in/trust/quit security flows.

The optional `restartMode: "restore-clean-workspace"` is a distinct bounded path for one trusted configured local file or untitled Workspace on the exact pinned default Windows version and commit. Preserve the default route when the key is absent. First snapshot and revalidate only the exact configured Workspace URI and ordered local roots around the marker-bound native probe and pinned install/process/sole-window checks. If native binding already works, return a minimal `restartRequired: false` receipt without inspecting or requiring clean documents/tabs, terminals, debugging, restore/close policy, kernels, background work, launch arguments or saved-state metadata; no quit authorization exists. Only when an actual restart is needed require strict restore/close policy, saved file-backed notebooks, no dirty or untitled documents/tabs, no terminals/debugging, supported local file tab inputs, affirmative no-kernel observations and no active or unsettled execution/setup/transfer work. Snapshot exact Workspace/root names and order, tab identities/multiplicity/group membership, pre-quit document identities/versions and bounded saved-state metadata; revalidate them exactly before and after helper arm and in the final synchronous pre-quit check under a process-local mutation exclusion. A per-request token keeps the same handle across old-active cleanup, port reservation and receipt construction; only the executing prepare request may transfer provisional ownership to a durable preparation ID, and polling or initialization cannot adopt its unbound handle. An older failed, ready or expired receipt cannot release or replace a newer preparation's block. A proven owning durable terminal receipt relinquishes only its durable ID while an in-progress prepare request retains the handle until safe exit or transfer to its new pending receipt. Loaded document identities/versions are a pre-quit mutation guard and are not compared after launch. Read only the relevant bounded `Code/Workspaces` and `storage.json` metadata, never backup payloads, and never clean stale state. The helper must durably disarm after any failed final check; failed disarm confirmation keeps the owning exclusion held. Relaunch with the fixed default-profile/debug-port arguments and no positional Workspace or `--new-window`, and persist a pre-spawn timestamp before process creation. Post-restore verification uses that pre-spawn bound rather than `launchedAt`, identifies the new main process independently of the spawned child PID, requires the exact Workspace/ordered roots/tab-group resource multiplicity, and rechecks the approved untitled-Workspace/no-empty-window invariants while allowing VS Code to prune workspace/folder backup counts. Once ready, polling checks only Workspace identity, trust and a fresh marker-bound native proof. Do not force, save, discard, convert workspaces, write configuration/trust/private state or claim runtime readiness. Reserve receipt space for helper/failure fields before claiming the active slot; only a proven owning durable terminal receipt may release an armed exclusion after request ownership has transferred.

`inspect_colab_environment_preflight` is app-wide and read-only. Aggregate only strict bounded per-peer counts/booleans, sanitized native-listener and process/install/version evidence, explicit blocker codes and the supported next operation. Bound every peer, including the local peer, to a short inspection deadline; malformed, oversized, rejected or timed-out peers become unavailable. Accept only generated UUID peer identities and strict version shapes at this boundary. Bound display labels by truncating Unicode code points; never reject an otherwise valid peer because its multi-root label is long. Never expose contents, paths, target URLs/titles, terminal launch state, broad arguments, environment or authentication. A debugger target catalog can show candidate workbench pages but cannot establish exact peer/window ownership without the marker-bound preparation probe. For the exact default local Windows VS Code 1.142.0 build at commit `6d62b1d5dace93a33b3a6d3eca1317bd5e15bcb1`, the extension's own public `ExtensionContext.logUri` may supply read-only window-ID evidence: validate the exact extension ID and default-profile `logs/<session>/window<ID>/exthost/<extension-id>` shape without reading or enumerating logs, then require one matching sanitized `code --status` row under the same verified main process. At the broker, mapping is verified only when every peer responds with strict fields, all peers report the same exact main PID/commit/native rows, derived IDs are unique, and their set equals the complete observed native-window set. Counts alone remain insufficient. Unsupported versions, commits, remote or malformed URIs, duplicates, extras, timeouts and mismatches stay unmapped. This correspondence is evidence only and must not change recommendation eligibility, empty-window checks, native marker binding, quit/restart behavior or restoration design. Recommend preparation only with complete, consistent single-peer/single-app-window evidence and route-appropriate per-window blockers resolved; native-listener observations outside that gate remain evidence for the existing marker-bound prepare revalidation, not an automatic recommendation. The application check reuses the automatic-restart launch-argument allowlist, so a previously bootstrapped debug-port/workspace launch can conservatively suppress recommendation without proving native readiness failed. Do not retain a reusable restart authorization until an explicit restart mode owns snapshot expiry and revalidation. Inspection must not save, close, focus, reload, restart, select a runtime or weaken the existing empty-window checks.

`configure_kernel(runtime: "colab")` owns normal Colab setup in `colabSetup.ts`, using the bounded native Chromium adapter in `colabNative.ts`; there is no Orca fallback. The existing `colabDesktop.ts` supplies shared types/errors and retains historical adapter regression coverage. Native setup requires a loopback debugging port, not VS Code's smoke-test driver. DOM projections and input writes are fixed internally; marker, picker, exact input, focus, row and CPU checks stay in the same synchronous renderer turn as each write. Without `serverAlias`, select CPU/Standard/Latest and create a unique alias. With an exact prior MCP alias, select only that existing server and never create a fallback; a uniquely mounted matching root may be reused only after fresh verification. Then pause at `awaiting_kernel_selection`. `list_setup_kernels` observes actual owned choices; `select_setup_kernel` accepts only an ID from that latest listing. Never infer a default kernel. After exact selection acknowledgement, run/remove only an owned temporary pass cell, mount the exact alias, and require fresh runtime/filesystem verification. Reuse an active runtime only after the same check. Preserve normal authentication, version/capability gates, exact editor/window binding, bounded UI projections, cross-window lease and lifecycle/cancellation accounting. Never select GPU/TPU/Upgrade, read private authentication stores, or use beta Colab APIs that need separate integration approval. Records are asynchronous and bounded; poll/cancel by setupId. Pending commands must retain the lease. A retained/edited/uncertain startup cell must not be deleted.
`check_colab` uses the public active idle Python kernel and one explicit or uniquely discovered registered Colab filesystem root. Its fresh nonce must match across both surfaces, Linux/Python/module diagnostics must validate, and cleanup must be confirmed before returning `verified: true`. It does not select/start a kernel, modify notebook cells, install packages, or inspect user data. Preserve kernel identity checks, operation locks, bounded execution, quarantine of unsettled work, and cleanup uncertainty. A successful check is point-in-time evidence, never cached readiness. The setup workflow automates normal picker/startup/mount steps; sign-in/security prompts and unsupported UI remain explicit blockers.
`mount_colab_server` recovers only the mount for an exact MCP-generated alias from a setup receipt. It requires the notebook's already active idle Python kernel, never selects/starts kernels, runs cells, or creates/removes servers, and shares the tracked setup lease/cancellation lifecycle. Reuse requires one exact alias-named Colab workspace root; a new mount requires one fresh matching root. Both paths require same-kernel nonce verification before readiness.

## Shared notebook and transfer contract

`edit_cells.edits[].metadata` is nbformat cell metadata. Inserts store it inside VS Code's native `cell.metadata.metadata`; edits/replacements shallow-merge that nested map while preserving the native envelope's cell ID, attachments, execution count, and other fields. Metadata tests must verify serialized `.ipynb` fields, not only successful edits or in-memory values.

Source line bounds are 1-based and inclusive, and explicit source truncation is reported. Saved outputs can remain stale after edits; execution refreshes observed output state. File transfer requires the public API of the current active idle Python kernel and never starts or selects a kernel. Files above 4 MiB use Colab's registered public filesystem provider, with a 64 MiB buffer cap and a kernel-created nonce proving the selected runtime before payload I/O. Smaller files retain bounded kernel chunks unless native transfer is explicitly selected. A chunk request carries its payload once (base64, zlib when it saves at least 10%), and every transfer request purges earlier tagged request sources from IPython's `linecache` (including IPython 7's `_ipython_cache`) so kernel memory does not grow with transferred bytes. Keep the per-kernel 64 MiB chunk-traffic budget; refuse before dispatch rather than risk the runtime. Never fall back to a large kernel transfer when native binding fails. Timeout/cancellation does not prove native filesystem I/O stopped; quarantine pending I/O and preserve uncertainty.

The `notebook.cell.execute` command is invoked with an explicit target editor and selected cell ranges. Runtime selection supplied by the user takes precedence; missing or ambiguous targets fail closed rather than opening or transferring another notebook.

`run_cells` creates a tracked execution before dispatch and returns a JSON receipt containing an opaque `executionId`, `status`, and bounded per-cell state. `waitMs` only bounds the caller's wait and never cancels the sequential background runner; its default is 1000, while `get_execution` defaults to 0 and is read-only. Both accept non-negative safe-integer waits, including hour-scale workflows. A run is retained only for the current extension-window lifetime, with at most one active run per notebook, bounded global active work, and bounded terminal history/retention. Cell identity and source hashes are captured at request time; edits, moves, deletion, closure, MCP-issued kernel restart/interrupt, or unavailable observation stop later submission safely.

Track dispatched cell-command settlement independently of observation generations and terminal-history retention. An interrupt can invalidate the execution record before Jupyter finishes rejecting the command. Expose `notebookCommandPending`, block another run and Colab setup while it remains pending, and include those notebooks in the global active-work bound. Resolve or reject may release this guard; history expiry, interruption or lost observation may not. Preserve synchronous command dispatch and sanitized errors. Provider selection keeps its existing coarse stage plus bounded `providerStep` / `failedProviderStep` names; do not expose arbitrary picker contents or infer authentication failures from a picker timeout.

Tracked execution must also observe public Jupyter kernel status events and serialized bounded identity lookups, including a fresh check before each cell. Latch lifecycle loss across rapid automatic restart back to idle, mark the old run `unavailable`, and do not dispatch later cells. Once bound, tolerate transient lookup failures/unknown state, with at most three consecutive unsuccessful observations; never dispatch the next cell using an uncertain observation. Preserve command-settlement quarantine and current source/identity guards. No heartbeat execution, automatic restart, interrupt, output-shaped crash inference or resource-cause claim is permitted. Dispose listeners/timers when tracking ends; a failed lookup means lost observation, not proof of OOM. A first cell may start a selected kernel that the public API has not exposed yet.

When the README comparison changes, recheck the linked primary sources and record the check date. Keep coverage bounded and do not repeat a full survey without a changed question or source.

## Safe development

Run `npm run typecheck` and `npm run compile` for structural checks. `npm test` runs the MCP, Jupyter integration, and compiled broker suites; isolate the broker with `npm run compile:test; node .vscode-test/broker.test.cjs` when needed. Do not dump credentials, raw notebook contents, or account fields. Changes, installs, and releases remain within the user-authorized scope.
